## Purpose

Определяет, откуда система берёт то, что различается между проектами: имя образа, список распознаваемых обёрток и обслуживание главного чекаута. Отвечает также за то, что настройками проекта не является, и за поведение при отсутствующих и при негодных настройках.

## Requirements

### Requirement: Настройки проекта задаются файлом

Система SHALL брать настройки, различающиеся между проектами, из файла настроек проекта. Файл SHALL искаться от рабочего каталога обрабатываемого вызова вверх по родительским каталогам; побеждает первый найденный. Обход SHALL останавливаться на границе репозитория, чтобы настройки постороннего родительского каталога не применялись к проекту.

Настройки SHALL принадлежать репозиторию, а не отдельному чекауту: связанное рабочее дерево, в котором своего файла нет, SHALL брать настройки главного чекаута того же репозитория. Копия файла в каждом рабочем дереве не требуется, и её отсутствие не SHALL отключать пул — рабочим деревьям пул и нужен в первую очередь. Собственный файл рабочего дерева SHALL побеждать файл репозитория. Переменных окружения для этих настроек не SHALL быть: настройка, не видимая в репозитории проекта, не переживает перезапуск сессии и не воспроизводится у второго участника.

#### Scenario: Файл в самом рабочем каталоге

- **WHEN** файл настроек лежит в рабочем каталоге вызова
- **THEN** система применяет его настройки

#### Scenario: Файл в родительском каталоге

- **WHEN** файл настроек лежит выше рабочего каталога, а между ними файла нет
- **THEN** система применяет настройки из найденного файла

#### Scenario: Файл найден на двух уровнях

- **WHEN** файл настроек есть и в рабочем каталоге, и выше него
- **THEN** применяется файл из ближайшего к рабочему каталогу уровня, без слияния значений

#### Scenario: Обход не переходит границу репозитория

- **WHEN** рабочий каталог принадлежит репозиторию, файла настроек в нём нет, а выше границы этого репозитория файл есть
- **THEN** настройки не применяются: файл считается ненайденным

#### Scenario: Рабочее дерево без своего файла

- **WHEN** рабочий каталог является связанным рабочим деревом без файла настроек, а в главном чекауте того же репозитория файл есть
- **THEN** применяются настройки главного чекаута, независимо от расположения рабочего дерева в файловой системе

#### Scenario: У рабочего дерева есть свой файл

- **WHEN** файл настроек есть и в связанном рабочем дереве, и в главном чекауте
- **THEN** применяется файл рабочего дерева

### Requirement: Состав настроек

Файл настроек SHALL содержать имя образа как обязательное поле: у образа для пула не существует общепринятого имени, поэтому дефолта у него быть не может.

Необязательными полями с дефолтами SHALL быть список распознаваемых обёрток и обслуживание главного чекаута. Прочие настройки — расположение реестра, диапазон портов, все пределы времени, включая предел простоя, предел одновременных инстансов, ускоритель графики, расположение журнала решений — настройками проекта не SHALL быть.

Предел одновременных инстансов не SHALL быть настройкой проекта: сколько инстансов помещается, определяют память и диск машины, а не репозиторий. Записанное в репозитории число воспроизводит у второго участника само число, но не поведение. Ускоритель графики не SHALL быть настройкой проекта: его значение обязано совпадать с ускорителем, записанным в снапшот загрузки образа, иначе снапшот не загружается и каждый инстанс молча выполняет полную загрузку, — то есть оно продиктовано образом, а не выбирается проектом.

#### Scenario: Заданы только обязательные поля

- **WHEN** файл настроек содержит только имя образа
- **THEN** остальные настройки принимают значения по умолчанию

#### Scenario: Задан предел инстансов

- **WHEN** файл настроек задаёт предел одновременных инстансов
- **THEN** файл негоден: код возврата равен 2, вызов заблокирован, а причина называет это поле

#### Scenario: Задан ускоритель графики

- **WHEN** файл настроек задаёт ускоритель графики
- **THEN** файл негоден: код возврата равен 2, вызов заблокирован, а причина называет это поле

#### Scenario: Задан предел простоя

- **WHEN** файл настроек задаёт предел простоя
- **THEN** файл негоден: код возврата равен 2, вызов заблокирован, а причина называет это поле

### Requirement: Отсутствие настроек означает отказ от обслуживания

Если файл настроек не найден, система не SHALL обслуживать вызов: вывод пуст, код возврата равен 0, вызов инструмента исполняется без вмешательства. Хук подключается общими настройками агента и приходит из любого проекта, поэтому отсутствие файла — это «проект не мой», а не ошибка.

Освобождение инстанса при завершении сессии SHALL происходить независимо от наличия файла настроек: реестр один на машину, и для освобождения имя образа не требуется.

Отметка активности сессии и уборка записей простаивающих сессий SHALL происходить независимо от наличия файла настроек, по тому же основанию: реестр один на машину, и ни для отметки, ни для уборки имя образа не требуется. Обслуживанием вызова это не является — исход обработки остаётся тем же, — а привязка к настройкам сделала бы уборку слепой ровно там, где нужнее всего: брошенная сессия перестаёт порождать события, и убирать за ней приходится сессиям других проектов.

#### Scenario: Обращение к эмулятору без файла настроек

- **WHEN** приходит вызов, обращающийся к эмулятору, а файл настроек не найден ни на одном уровне
- **THEN** вывод пуст, код возврата равен 0, инстанс не выдаётся

#### Scenario: Завершение сессии без файла настроек

- **WHEN** приходит завершение сессии, которой инстанс выдавался, а файл настроек не найден
- **THEN** инстанс освобождается

#### Scenario: Уборка по простою без файла настроек

- **WHEN** приходит вызов из проекта без файла настроек, а в реестре есть запись простаивающей сессии
- **THEN** эта запись убирается, при этом вывод пуст, код возврата равен 0, а вызов исполняется без вмешательства

### Requirement: Негодные настройки блокируют вызов

Если файл настроек найден, но применить его нельзя, система SHALL завершаться кодом 2 с описанием причины на стандартном потоке ошибок, что блокирует вызов инструмента. Найденный файл означает, что проект настраивался сознательно, поэтому продолжать на значениях по умолчанию нельзя: это увело бы вызов на инстанс не того образа либо оставило бы обращение непривязанным.

Негодными SHALL считаться: неразбираемое содержимое, отсутствие обязательного поля, незнакомое поле, значение неподходящего типа, элемент списка обёрток, не являющийся годной регуляркой. Незнакомое поле SHALL быть ошибкой, а не игнорироваться: иначе опечатка в имени поля неотличима от работающей настройки.

#### Scenario: Неразбираемое содержимое

- **WHEN** файл настроек найден, но его содержимое не разбирается
- **THEN** код возврата равен 2, а причина описана на стандартном потоке ошибок

#### Scenario: Обязательное поле отсутствует

- **WHEN** файл настроек не содержит имени образа
- **THEN** код возврата равен 2, а причина называет отсутствующее поле

#### Scenario: Незнакомое поле

- **WHEN** файл настроек содержит поле, которого система не знает
- **THEN** код возврата равен 2, а причина называет это поле

#### Scenario: Негодная регулярка в списке обёрток

- **WHEN** элемент списка распознаваемых обёрток не является годной регуляркой
- **THEN** код возврата равен 2, а причина называет негодный элемент

#### Scenario: Завершение сессии при негодных настройках

- **WHEN** приходит завершение сессии, которой инстанс выдавался, а найденный файл настроек негоден
- **THEN** инстанс освобождается: блокировать при завершении сессии нечего, и для освобождения настройки не требуются

### Requirement: Список распознаваемых обёрток задаётся проектом

Обёртки, через которые проект обращается к эмулятору, SHALL перечисляться в настройках проекта, а не в системе. Элемент списка SHALL быть регуляркой, сопоставляемой с одним словом команды; требование позиции команды SHALL обеспечиваться системой, а не автором элемента. Гарантия «упоминание слова внутри текста или кавычек не приводит к выдаче инстанса» не SHALL зависеть от того, насколько аккуратно составлен элемент списка.

#### Scenario: Обращение через настроенную обёртку

- **WHEN** команда вызывает обёртку, перечисленную в настройках, в позиции команды
- **THEN** система распознаёт обращение к эмулятору и выдаёт инстанс

#### Scenario: Имя настроенной обёртки внутри текста

- **WHEN** имя перечисленной обёртки встречается в команде только внутри кавычек или как часть текста
- **THEN** инстанс не выдаётся

#### Scenario: Список обёрток не задан

- **WHEN** файл настроек не содержит списка обёрток
- **THEN** распознаются только обращения, входящие в ядро распознавания

### Requirement: Расположение SDK определяется окружением

Расположение SDK не SHALL быть настройкой проекта: это свойство машины, а не проекта. Система SHALL определять его по общепринятым переменным окружения, а при их отсутствии — по стандартному расположению для текущей платформы. Поддерживаемые платформы — macOS и Linux; стандартные расположения у них различаются.

#### Scenario: Расположение задано окружением

- **WHEN** окружение задаёт расположение SDK любой из общепринятых переменных
- **THEN** система использует заданное расположение

#### Scenario: Расположение не задано

- **WHEN** ни одна из общепринятых переменных не задана
- **THEN** система использует стандартное расположение для текущей платформы

### Requirement: Реестр один на машину

Реестр SHALL быть один на машину. Занятые инстансы SHALL учитываться в общем числе независимо от того, из какого проекта они заняты: порты, память и диск у проектов общие. Разделение реестра по проектам не SHALL вводиться: уборка не трогает инстансы, отсутствующие в её реестре, поэтому два реестра дают две уборки, каждая слепая к портам и слоям другой, а взаимное исключение запусков перестаёт быть машинным.

#### Scenario: Занятость видна между проектами

- **WHEN** инстансы заняты сессиями одного проекта и за инстансом обращается сессия другого проекта
- **THEN** обращение учитывает уже занятые инстансы в пределе одновременных инстансов

#### Scenario: Освобождение не зависит от проекта

- **WHEN** приходит завершение сессии, которой инстанс выдавался, и рабочий каталог сессии не определяет проект
- **THEN** инстанс освобождается: он отыскивается в реестре по идентификатору сессии
