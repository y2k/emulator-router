## Purpose

Привязывает каждый вызов инструмента, способный дотянуться до Android-эмулятора, к тому инстансу, который принадлежит текущей сессии, и запрещает вызовы, разрушающие пул целиком. Сессия при этом не обязана знать свой серийник.

## Requirements

### Requirement: Обработка событий хука

Система SHALL принимать на стандартный вход JSON события хука и обрабатывать события `PreToolUse` и `SessionEnd`. Решение SHALL выдаваться на стандартный выход в формате `hookSpecificOutput`. Отсутствие вывода при нулевом коде возврата означает «вызов разрешён без изменений».

#### Scenario: Событие, которое система не обрабатывает

- **WHEN** на вход приходит событие с `hook_event_name`, отличным от `PreToolUse` и `SessionEnd`
- **THEN** вывод пуст и код возврата равен 0

#### Scenario: Имя инструмента, к которому система отношения не имеет

- **WHEN** приходит `PreToolUse` с `tool_name`, не относящимся ни к `Bash`, ни к инструментам Mobile-MCP
- **THEN** вывод пуст и код возврата равен 0, поскольку это ошибка настройки сопоставителя, а не отказ системы

### Requirement: Право на инстанс определяется рабочим каталогом

Система SHALL выдавать инстанс из пула только тем сессиям, для рабочего каталога которых найден файл настроек проекта. Отсутствие файла разбирается способностью настроек: система не вмешивается в вызов.

При найденном файле настроек система SHALL выдавать инстанс только тем сессиям, чей рабочий каталог не является главным чекаутом git-репозитория. В главном чекауте выбор устройства SHALL оставаться за пользователем, и система не SHALL вмешиваться в вызов. Настройки проекта SHALL позволять отменить это исключение: проект, работающий без связанных рабочих деревьев, иначе не получает пул вовсе.

Рабочий каталог, не относящийся к git-репозиторию, SHALL обслуживаться наравне со связанным рабочим деревом. Это зафиксированное решение, а не следствие реализации: сужение правила до «только связанное рабочее дерево» является отдельным изменением поведения.

#### Scenario: Главный чекаут

- **WHEN** приходит `PreToolUse` с рабочим каталогом, чей каталог git совпадает с общим каталогом git
- **THEN** вывод пуст и код возврата равен 0

#### Scenario: Подкаталог главного чекаута

- **WHEN** рабочий каталог является вложенным каталогом главного чекаута
- **THEN** поведение совпадает с поведением для самого главного чекаута

#### Scenario: Главный чекаут при включённом обслуживании

- **WHEN** рабочий каталог является главным чекаутом, а настройки проекта включают его обслуживание
- **THEN** система обрабатывает вызов и при необходимости выдаёт инстанс

#### Scenario: Связанное рабочее дерево

- **WHEN** рабочий каталог является связанным рабочим деревом
- **THEN** система обрабатывает вызов и при необходимости выдаёт инстанс

#### Scenario: Каталог вне git-репозитория

- **WHEN** рабочий каталог не относится ни к одному git-репозиторию, а файл настроек найден выше него
- **THEN** система обрабатывает вызов наравне со связанным рабочим деревом

### Requirement: Освобождение при завершении сессии безусловно

Система SHALL освобождать инстанс сессии при событии `SessionEnd` независимо от рабочего каталога, включая главный чекаут. Инстансы, выданные до введения правила о рабочем каталоге, должны освобождаться так же, как все остальные.

#### Scenario: Завершение сессии в главном чекауте

- **WHEN** приходит `SessionEnd` с рабочим каталогом главного чекаута
- **THEN** инстанс, принадлежащий этой сессии, освобождается

#### Scenario: Завершение сессии без выданного инстанса

- **WHEN** приходит `SessionEnd` для сессии, которой инстанс не выдавался
- **THEN** система завершается успешно, ничего не освобождая

### Requirement: Запреты проверяются до выдачи инстанса

Система SHALL проверять все запреты и все условия отказа от обработки прежде, чем обращаться за инстансом. Вызов, который будет запрещён, не SHALL приводить к запуску эмулятора.

#### Scenario: Запрещённая команда при исчерпанном пуле

- **WHEN** приходит запрещённая команда, и в пуле нет свободных мест
- **THEN** решение содержит причину запрета этой команды, а не сообщение об исчерпании пула

### Requirement: Читающие проверки не расходуют место в пуле

Система SHALL пропускать без выдачи инстанса вызовы, которые только перечисляют или опрашивают состояние подсистемы отладки: перечисление устройств, запрос версии, запуск сервера отладки, перечисление доступных устройств через Mobile-MCP.

#### Scenario: Перечисление устройств

- **WHEN** команда состоит только из запроса перечисления подключённых устройств, с флагом подробного вывода или без него
- **THEN** вывод пуст, код возврата равен 0, инстанс не выдаётся

#### Scenario: Перечисление доступных устройств через Mobile-MCP

- **WHEN** приходит вызов инструмента перечисления доступных устройств
- **THEN** вывод пуст, код возврата равен 0, инстанс не выдаётся

### Requirement: Обращение к эмулятору распознаётся по команде

Система SHALL распознавать команды оболочки, обращающиеся к эмулятору, и не SHALL вмешиваться в остальные. Распознавание SHALL требовать, чтобы имя программы стояло в позиции команды — в начале строки либо после разделителя команд, — так что упоминание того же слова внутри текста или кавычек не приводит к выдаче инстанса.

Позиция команды SHALL допускать перед именем программы присваивания переменных окружения, действующие только на эту команду: для оболочки команда с таким префиксом — та же команда, и префикс не должен выводить её из-под распознавания и запретов. Определение начала команды SHALL быть общим для распознавания и для запретов. Значение присваивания в кавычках с пробелами разбирать не требуется.

Ядро распознавания SHALL состоять из обращений, общих для любого проекта с Android-эмулятором: программа отладки, программа эмулятора, сборочная обёртка проекта в режимах установки и запуска на подключённом устройстве. Обёртки конкретного проекта SHALL добавляться настройками проекта, а не входить в ядро.

Набор распознаваемых обращений заведомо неполон: ложноотрицательное срабатывание — принятый компромисс, а не дефект.

#### Scenario: Команда, не имеющая отношения к эмулятору

- **WHEN** приходит команда, не содержащая обращения к эмулятору
- **THEN** вывод пуст, код возврата равен 0, инстанс не выдаётся

#### Scenario: Имя программы внутри текста

- **WHEN** слово, совпадающее с именем распознаваемой программы, встречается в команде только внутри кавычек или как часть текста, а не в позиции команды
- **THEN** инстанс не выдаётся

#### Scenario: Обращение после разделителя команд

- **WHEN** обращение к эмулятору стоит во второй части составной команды, после разделителя
- **THEN** система распознаёт обращение и выдаёт инстанс

#### Scenario: Обращение с присваиванием окружения

- **WHEN** обращению к эмулятору или к обёртке проекта предшествуют присваивания переменных окружения
- **THEN** система распознаёт обращение и выдаёт инстанс

#### Scenario: Присваивание окружения внутри кавычек

- **WHEN** присваивание и следующее за ним имя распознаваемой программы встречаются только внутри кавычек
- **THEN** инстанс не выдаётся

#### Scenario: Обращение через программу-обёртку

- **WHEN** обращение к эмулятору предваряется программой-обёрткой, отвязывающей процесс от терминала, либо интерпретатором оболочки
- **THEN** система распознаёт обращение и выдаёт инстанс

#### Scenario: Обращение через обёртку проекта

- **WHEN** приходит команда, вызывающая обёртку, перечисленную в настройках проекта
- **THEN** система распознаёт обращение и выдаёт инстанс

### Requirement: Запрет получения прав суперпользователя для демона отладки

Система SHALL запрещать команды, перезапускающие демон отладки в режиме суперпользователя. Такой перезапуск переводит в недоступное состояние все инстансы пула, включая принадлежащие другим сессиям.

Причина отказа SHALL называть замену — выполнение отдельной команды с правами суперпользователя — не утверждая при этом, что образ собран в отладочной конфигурации: конфигурация образа задаётся проектом и системе неизвестна.

#### Scenario: Запрос прав суперпользователя для демона отладки

- **WHEN** приходит команда, переводящая демон отладки в режим суперпользователя, с явным указанием устройства или без него
- **THEN** решение запрещает вызов и называет способ выполнить команду с правами суперпользователя без перезапуска демона

#### Scenario: Запрос прав суперпользователя с присваиванием окружения

- **WHEN** той же команде предшествуют присваивания переменных окружения
- **THEN** решение запрещает вызов

### Requirement: Запрет запуска пулового образа в режиме записи

Система SHALL запрещать запуск образа, используемого пулом, без указания режима только для чтения. Запуск в режиме записи уничтожает снапшот загрузки образа, после чего каждый инстанс пула вместо загрузки из снапшота выполняет полную загрузку.

Проверка SHALL относиться только к образу, используемому пулом; запуск других образов SHALL проходить без вмешательства. Имя образа SHALL сопоставляться как литерал, а не как шаблон.

#### Scenario: Запуск пулового образа без режима только для чтения

- **WHEN** приходит команда запуска пулового образа без указания режима только для чтения
- **THEN** решение запрещает вызов и называет последствие для снапшота

#### Scenario: Запуск пулового образа через программу-обёртку

- **WHEN** та же команда предваряется программой-обёрткой, отвязывающей процесс от терминала
- **THEN** решение запрещает вызов

#### Scenario: Запуск пулового образа с присваиванием окружения

- **WHEN** той же команде предшествуют присваивания переменных окружения
- **THEN** решение запрещает вызов

#### Scenario: Запуск пулового образа в режиме только для чтения

- **WHEN** приходит команда запуска пулового образа с указанием режима только для чтения
- **THEN** запрет не срабатывает, и система переходит к выдаче инстанса

#### Scenario: Запуск другого образа

- **WHEN** приходит команда запуска образа, не используемого пулом, без режима только для чтения
- **THEN** запрет не срабатывает

### Requirement: Привязка команды оболочки к своему инстансу

Для команды, обращающейся к эмулятору, система SHALL выдать изменённую команду, в которой обращение направлено на инстанс этой сессии:

- явное указание целевого устройства SHALL быть заменено на серийник этой сессии во всех вхождениях, включая составные команды;
- сокращённое указание «единственный эмулятор» SHALL быть заменено явным указанием серийника, поскольку при нескольких запущенных инстансах оно неоднозначно;
- серийник SHALL передаваться также через переменные окружения, объявленные так, чтобы действовать на все команды в составной команде, а не только на первую.

Дописывание аргументов в вызовы обёрток проекта не SHALL выполняться: обёртка получает серийник переменными окружения и отвечает за то, чтобы их уважать.

Система SHALL сообщать модели серийник её инстанса, чтобы устройство не выбиралось из перечисления устройств.

#### Scenario: Явное указание чужого устройства

- **WHEN** команда содержит явное указание устройства, отличного от инстанса этой сессии
- **THEN** указание заменяется на серийник этой сессии

#### Scenario: Несколько обращений в одной команде

- **WHEN** команда содержит несколько обращений с явным указанием устройства
- **THEN** заменяются все вхождения

#### Scenario: Сокращённое указание единственного эмулятора

- **WHEN** команда использует сокращённое указание «единственный эмулятор»
- **THEN** оно заменяется явным указанием серийника этой сессии

#### Scenario: Обращение во второй части составной команды

- **WHEN** обращение к эмулятору стоит после разделителя, а первая часть команды меняет каталог
- **THEN** переменные окружения с серийником действуют и на это обращение

#### Scenario: Сценарий, выбирающий устройство самостоятельно

- **WHEN** команда вызывает сценарий, который при отсутствии указания берёт первое подключённое устройство, и указание не задано
- **THEN** аргументы к вызову не дописываются, а привязка обеспечивается переменными окружения с серийником

#### Scenario: Указание задано вызывающим

- **WHEN** тот же сценарий вызван с уже заданным указанием устройства в собственном формате обёртки
- **THEN** указание остаётся без изменений: система не разбирает аргументы обёрток

#### Scenario: Сообщение серийника модели

- **WHEN** система выдаёт изменённую команду
- **THEN** решение содержит дополнительный контекст, называющий серийник инстанса этой сессии

### Requirement: Привязка вызова Mobile-MCP к своему инстансу

Для вызовов инструментов Mobile-MCP, кроме перечисления доступных устройств, система SHALL подменять аргумент выбора устройства на серийник инстанса этой сессии.

#### Scenario: Вызов с чужим устройством

- **WHEN** приходит вызов инструмента Mobile-MCP с аргументом устройства, отличным от инстанса этой сессии
- **THEN** аргумент заменяется на серийник этой сессии

#### Scenario: Вызов без аргумента устройства

- **WHEN** приходит вызов инструмента Mobile-MCP без аргумента устройства
- **THEN** аргумент устройства задаётся равным серийнику этой сессии

### Requirement: Владельцем инстанса считается процесс сессии

Система SHALL определять владельца как ближайший процесс-предок, соответствующий процессу сессии, а не непосредственного родителя, поскольку непосредственный родитель — одноразовая оболочка. Время жизни этого процесса совпадает со временем жизни сессии.

Субагенты SHALL получать тот же инстанс, что и сессия, их запустившая, даже если сообщают собственный идентификатор сессии, поскольку разделяют с ней процесс владельца.

#### Scenario: Вызов из субагента

- **WHEN** приходит вызов с идентификатором сессии, отличным от идентификатора сессии-владельца, но с тем же процессом-владельцем
- **THEN** выдаётся тот же инстанс, что уже принадлежит этому владельцу

#### Scenario: Процесс сессии не найден

- **WHEN** среди процессов-предков нет процесса сессии
- **THEN** система продолжает обработку, считая владельца неопределённым, и опирается только на идентификатор сессии

### Requirement: Невозможность выдать инстанс приводит к запрету вызова

Если команда распознана как обращение к эмулятору, но инстанс выдать не удалось, система SHALL запретить вызов и SHALL включить в причину сообщение об ошибке выдачи. Вызов не SHALL исполняться без привязки к инстансу.

#### Scenario: Пул исчерпан

- **WHEN** команда обращается к эмулятору, а все места в пуле заняты
- **THEN** решение запрещает вызов, а причина содержит сообщение об исчерпании пула

#### Scenario: Инстанс не смог загрузиться

- **WHEN** команда обращается к эмулятору, а запуск инстанса завершился неудачей
- **THEN** решение запрещает вызов, а причина содержит сообщение о неудачном запуске

### Requirement: Внутренняя ошибка не приводит к неприкреплённому вызову

При внутренней ошибке обработки события `PreToolUse` система SHALL завершаться кодом 2 с описанием причины на стандартном потоке ошибок, что блокирует вызов. Код возврата, при котором вызов исполняется, не SHALL использоваться для внутренних ошибок: вызов без привязки к инстансу уходит на произвольное устройство, возможно принадлежащее другой сессии.

Для события `SessionEnd` блокировать нечего, поэтому ошибка освобождения SHALL сообщаться кодом 1.

#### Scenario: Нечитаемый вход

- **WHEN** стандартный вход не является разбираемым JSON
- **THEN** код возврата равен 2, а причина описана на стандартном потоке ошибок

#### Scenario: Отсутствует идентификатор сессии

- **WHEN** событие `PreToolUse` не содержит идентификатора сессии
- **THEN** код возврата равен 2

#### Scenario: Отсутствует команда

- **WHEN** событие `PreToolUse` относится к запуску команды оболочки, но команда не задана
- **THEN** код возврата равен 2

#### Scenario: Отсутствует рабочий каталог

- **WHEN** событие `PreToolUse` не содержит рабочего каталога
- **THEN** используется рабочий каталог самого процесса, и обработка продолжается

#### Scenario: `SessionEnd` без идентификатора сессии

- **WHEN** событие `SessionEnd` не содержит идентификатора сессии
- **THEN** код возврата равен 1, а причина описана на стандартном потоке ошибок

#### Scenario: Ошибка при освобождении

- **WHEN** обработка события `SessionEnd` завершается ошибкой
- **THEN** код возврата равен 1, а причина описана на стандартном потоке ошибок

### Requirement: Выдача инстанса укладывается во внешний предел времени

Система SHALL завершать обработку события явным решением прежде, чем вызывающая
сторона прервёт её по своему пределу времени. Прерванная обработка не блокирует
вызов инструмента: он исполняется без привязки к инстансу и уходит на
произвольное устройство, тогда как отказ с причиной оставляет выбор устройства
под контролем системы. Поэтому собственный предел ожидания SHALL существовать и
SHALL быть заведомо меньше предела, действующего у вызывающей стороны по
умолчанию.

Исчерпание собственного предела SHALL приводить к отказу, причина которого
называет происходящее и предлагает повторить вызов. Незавершённая загрузка при
этом не SHALL прерываться: она продолжается, и обращение, пришедшее позже,
получает уже готовый инстанс. Прежний запрет на собственный предел отменяется
именно так — не обрывом загрузки, а отказом на время её продолжения.

#### Scenario: Выдача требует полной загрузки инстанса

- **WHEN** свободного готового инстанса нет и требуется загрузка нового, а
  собственный предел ожидания ещё не исчерпан
- **THEN** система ожидает загрузку, не прерывая её раньше

#### Scenario: Собственный предел ожидания исчерпан

- **WHEN** ожидание выдачи достигает собственного предела системы
- **THEN** решение запрещает вызов, называет причину и предлагает повторить, а
  код возврата не оставляет вызов исполняться без привязки

#### Scenario: Начатая загрузка переживает исчерпание предела

- **WHEN** предел ожидания исчерпан, пока инстанс ещё загружался
- **THEN** загрузка продолжается, а следующее обращение той же сессии получает
  этот инстанс, не запуская второй

#### Scenario: Собственный предел меньше внешнего

- **WHEN** обработка события укладывается в собственный предел ожидания
- **THEN** она завершается решением раньше, чем истекает предел, действующий у
  вызывающей стороны по умолчанию

### Requirement: Изменённый ввод сохраняет остальные аргументы вызова

Изменённый ввод в решении заменяет ввод вызова целиком, а не сливается с ним по
полям. Поэтому система SHALL включать в изменённый ввод все поля исходного ввода
вызова, переопределяя только те, которыми вызов привязывается к инстансу:
аргумент выбора устройства у вызовов Mobile-MCP и команду у вызовов оболочки.
Поля, значения которых не являются строками, SHALL передаваться с сохранением
своего типа.

Утрата поля не сводится к потере удобства. Обязательный аргумент инструмента
Mobile-MCP делает вызов негодным по схеме самого инструмента, а признак фонового
исполнения и предел времени у вызова оболочки меняют способ исполнения команды:
вызванная в фоне сборка становится синхронной и прерывается по дефолтному
пределу.

Система не SHALL добавлять в изменённый ввод поля, которых не было в исходном
вводе, кроме переопределяемых: значение по умолчанию, выдуманное системой,
неотличимо для инструмента от заданного вызывающей стороной.

#### Scenario: Вызов Mobile-MCP с обязательными аргументами помимо устройства

- **WHEN** приходит вызов инструмента Mobile-MCP, обязательные аргументы которого
  включают не только устройство, и часть их значений не является строками
- **THEN** изменённый ввод содержит все эти аргументы с исходными значениями и
  типами, а аргумент устройства заменён на серийник инстанса этой сессии

#### Scenario: Вызов оболочки с признаком фонового исполнения

- **WHEN** приходит вызов оболочки, обращающийся к эмулятору, с заданным
  признаком фонового исполнения
- **THEN** изменённый ввод содержит этот признак с исходным значением, а команда
  переопределена привязкой к инстансу этой сессии

#### Scenario: Вызов оболочки с заданным пределом времени

- **WHEN** приходит вызов оболочки, обращающийся к эмулятору, с заданным пределом
  времени исполнения
- **THEN** изменённый ввод содержит этот предел с исходным значением

#### Scenario: Вызов без дополнительных аргументов

- **WHEN** исходный ввод вызова не содержит полей, кроме переопределяемого, либо
  пуст
- **THEN** изменённый ввод содержит только переопределённое поле

### Requirement: Обработка события отмечает активность сессии и убирает простой

Обработка события хука SHALL начинаться с двух действий: отметки активности своей сессии в реестре и уборки записей, чьи сессии простаивают. Оба действия SHALL выполняться прежде разбора настроек проекта и прежде всех условий, при которых система в вызов не вмешивается, — и независимо от их исхода.

Отметка SHALL ставиться при любом обработанном событии, включая те, что заканчиваются пустым выводом: читающую проверку, нераспознанную команду, вызов из главного чекаута, вызов из проекта без файла настроек. Иначе сессия, работающая не с устройством, выглядела бы брошенной, и её инстанс отобрали бы у работающего.

Уборка по простою SHALL выполняться при обработке события независимо от того, обращается ли вызов за инстансом. Хук подключается общими настройками агента и приходит из любого проекта, поэтому любая живая сессия машины убирает за всеми — включая те случаи, до которых `SessionEnd` не доходит: аварийно завершённую сессию, спящую машину, сессию с неизвестным владельцем.

Ни отметка, ни уборка по простою не SHALL менять исход обработки вызова: в проекте без файла настроек вывод остаётся пустым, код возврата — нулевым, а вызов исполняется без вмешательства. Реестр один на машину, и ни для отметки, ни для уборки имя образа не требуется — как и для освобождения при завершении сессии.

#### Scenario: Событие в проекте без файла настроек

- **WHEN** приходит событие хука из проекта, для которого файл настроек не найден
- **THEN** активность сессии отмечается, простаивающие записи убираются, вывод пуст, код возврата равен 0

#### Scenario: Событие с негодными настройками

- **WHEN** приходит событие хука из проекта, чей файл настроек найден, но негоден
- **THEN** активность сессии отмечается, простаивающие записи убираются, а вызов блокируется, как того требует негодность настроек

#### Scenario: Читающая проверка

- **WHEN** приходит вызов, только опрашивающий состояние подсистемы отладки
- **THEN** активность сессии отмечается, инстанс не выдаётся

#### Scenario: Запрещённый вызов

- **WHEN** приходит вызов, который будет запрещён
- **THEN** активность сессии отмечается, простаивающие записи убираются, и решением остаётся запрет

#### Scenario: Завершение сессии

- **WHEN** приходит событие завершения сессии
- **THEN** инстанс этой сессии освобождается, а записи простаивающих сессий убираются
