## Context

Мотивация описана в proposal.md (раздел Why), требования — в дельтах спек.
Решения ниже опираются на спайк 2026-11-13: образ `agent_base` (android-36,
google_apis, arm64), эмулятор 37.2.12, порт 5700 вне диапазона пула.

| Проверка | Результат |
|---|---|
| `-read-only -dns-server 10.0.0.53,192.0.2.53` | снапшот `default_boot` загружается, загрузка 4 с |
| DNS, которые видит гость | `10.0.2.3`: число адресов берётся из снапшота, а не из флага |
| имя стенда, google, S3 при корпоративном сервере первым | резолвятся, без правки hosts |
| `-dns-server 10.255.255.1,192.0.2.53` (первый недоступен) | IP-сеть работает, не резолвится ничего: второй сервер не используется |

Сейчас форма запуска инстанса записана прямо в `acquire` (`pool.go`, вызов
`c.Spawn(...)`), а идентичность инстанса проверяется условием `e.Image != c.AVD`
внутри `mine`. Добавлять туда DNS по месту значит размазать его по двум
функциям, у которых и так много обязанностей.

## Goals / Non-Goals

**Goals:**

- Весь код DNS лежит в отдельном файле `dns.go`. Остальной код касается его в
  нескольких местах, по одной строке в каждом.
- Отключение в коде делается в одном месте: строка в `acquire`, которая
  определяет сервер. Без неё сервер всегда пустой, флаг не передаётся,
  идентичность совпадает. Отключение для проекта — убрать поле `dns`.
- Проект без поля `dns` не замечает изменения ни по поведению, ни по стоимости:
  `scutil` не вызывается.

**Non-Goals:**

- Split DNS на Linux и Windows. `scutil` там нет, резолвер не находится, и
  инстанс запускается как сейчас.
- Несколько доменов с разными серверами. Гость пользуется одним сервером, так
  что второй домен с другим сервером всё равно не обслужить. Список станет
  нужен, только если у разных зон проекта окажется один сервер, а тогда
  хватает их общей родительской зоны.
- Живая проверка в `doctor`, что имя корпоративной зоны резолвится внутри
  инстанса: годного для такой проверки имени в настройках нет, у самого домена
  A-записи может и не быть.
- Запись в hosts гостевой системы: нужны root, IP по каждому хосту, и правка
  пропадает с каждым новым инстансом.

## Decisions

### 1. Сначала рефакторинг без изменения поведения

Из `acquire` и `mine` выносятся две функции:

- `launchArgs(ctx, port) []string` — аргументы запуска эмулятора, которые
  сейчас перечислены в вызове `c.Spawn`;
- `foreign(ctx, e entry) string` — причина, по которой инстанс записи не свой
  для обрабатываемого вызова, либо пустая строка. Сейчас это одно условие про
  образ и строка причины `image-mismatch` в `mine`.

Рефакторинг проходит существующими тестами без их правки. После него DNS
добавляет в `launchArgs` одну строку и в `foreign` одно условие.

Альтернативы:

- Интерфейс «опция запуска» с регистрацией реализаций. Отвергнут: реализация
  была бы одна, а одна строка в `launchArgs` даёт ту же изоляцию.
- Вложенная структура «профиль запуска» (`Image` + `DNS`) в `entry`. JSON
  остаётся совместимым, но все литералы `entry{..., Image: ...}` в тестах
  пришлось бы переписывать ради одного нового поля.

### 2. Сервер определяется один раз за выдачу и едет в `config`

В начале `acquire` одна строка `ctx = withHostDNS(ctx)` из `dns.go`. Если поле
`dns` задано, она читает `scutil --dns` через шов `run` и кладёт найденный
сервер в `config.DNSServer`. Дальше `foreign`, `launchArgs` и запись реестра
берут значение из `cfg(ctx)`, и оно одно и то же на всю выдачу.

Почему не в `applySettings`: настройки применяются на каждом `PreToolUse`,
включая вызовы, которые к устройству не обращаются, и внешняя команда там
стоила бы вызова на каждом инструменте. К тому же `applySettings` сейчас без
внешних эффектов, и тесты разбора на это опираются.

Освобождение не меняется: `release` приходит с настройками по умолчанию, где
нет ни образа, ни домена, и срабатывает уже на несовпадении образа.

### 3. Источник — `scutil --dns`, правило выбора — самая точная зона

Разбирается только первая секция вывода, до заголовка
`DNS configuration (for scoped queries)`. Резолвер — блок `resolver #N`, из
него берутся `domain` и `nameserver[0]`. Блоки без домена (основной резолвер)
или без сервера (mDNS `local`, обратные зоны) пропускаются.

Домен из настроек нормализуется: строчные буквы, без завершающей точки.
Резолвер подходит, если его зона равна домену или является родительской по
границе метки (`domain == d` или `HasSuffix(domain, "."+d)`). Из подходящих
выбирается самая длинная зона, при равенстве — первая в выводе. Так macOS сама
выбирает резолвер для имени, поэтому эмулятор получает тот же сервер, что
получил бы `dscacheutil` на этой машине.

Альтернативы:

- Файлы `/etc/resolver/*`. Отвергнуты: VPN-клиенты заводят резолверы через
  динамическое хранилище configd, а не файлами.
- «Первый supplemental-резолвер» без домена. Отвергнут вместе с вариантом
  флага: на машине бывают Tailscale и Docker, и выбор становится угадыванием.

### 4. Один сервер, а не список

Передаётся только `nameserver[0]` выбранного резолвера. По спайку гость
пользуется одним сервером, поэтому второй в списке и основной резолвер машины
в качестве запасного ничего не дают.

### 5. DNS-сервер входит в идентичность инстанса

В `entry` добавляется `DNS string \`json:"dns,omitempty"\``. Записи прежних версий
читаются с пустым сервером и совпадают с проектом без поля `dns`. `foreign`
проверяет сначала образ, затем DNS. Причина в журнале:
`reason=dns-mismatch was=<сервер|none> want=<сервер|none>`.

Альтернативы:

- Фиксировать DNS при запуске и не сравнивать. Отвергнуто: после выключения
  VPN инстанс остаётся без DNS до освобождения, а это та же молчаливая
  поломка, которую изменение устраняет.
- Перезапускать только при переходе «был сервер → нет сервера». Отвергнуто:
  обратный переход «не было → есть» — это и есть исходная проблема (VPN
  включили после запуска инстанса).

### 6. Проверка значения поля

В `applySettings` значение нормализуется (см. решение 3). Пустая строка и
значение, которое разбирается `net.ParseIP`, делают файл негодным; причина
называет поле и говорит, что сервер берётся из конфигурации машины. Синтаксис
домена дальше не проверяется: опечатка в домене просто не совпадёт ни с одним
резолвером, а это `doctor` назовёт предупреждением.

### 7. Ошибка чтения конфигурации равна отсутствию резолвера

Если `scutil` не запустился или вернул ошибку, сервер пустой, и инстанс
запускается как без настройки. DNS-сервер улучшает работу пула, но
предусловием не является, и блокировать из-за него обращения к устройству
хуже.

### 8. Журнал и `doctor`

Запись о запуске получает `dns=<сервер>` перед `cwd` (cwd остаётся последним:
в нём бывают пробелы), и только когда сервер задан. `doctor` в статических
проверках, если поле `dns` задано, вызывает тот же выбор резолвера: найден —
`pass` с доменом и сервером, не найден — `warn` с подсказкой про VPN.

## Risks / Trade-offs

- [Переключение VPN посреди сессии завершает инстанс, и установленное
  приложение пропадает] → Причина `dns-mismatch` попадает в журнал
  (`emulator-router log`). VPN переключают редко, а инстанс с неверным DNS
  ломает работу молча, что хуже.
- [Корпоративный DNS не рекурсивный, и публичные имена в инстансе не
  резолвятся] → Запасного сервера у гостя нет (решение 4), обойти это нельзя.
  На проверенной машине оба корпоративных сервера рекурсивные. Если домен на
  такой машине не работает, поле `dns` убирается.
- [Разовый сбой `scutil` у инстанса с сервером даёт `dns-mismatch` и
  перезапуск] → `scutil` читает локальный configd и на практике не падает.
  Если это начнёт случаться, при ошибке чтения пропускать сравнение.
- [Вызов `scutil` на каждой выдаче] → Только в проектах с полем `dns`. Это
  локальный вызов на миллисекунды, тогда как выдача и без него запускает `adb`
  и `pgrep`.
- [Первые ~10 с после загрузки из снапшота DNS в гостевой системе не работает,
  пока переподключается WiFi] → Это было и до изменения и от флага не
  зависит; изменение этого не касается.

## Migration Plan

Миграции нет: записи реестра совместимы, без поля `dns` поведение прежнее. Для
рабочего Android-проекта после выпуска нужно добавить `"dns": "corp.example"` в его
`.claude/emulator-router.json`. Откат — убрать поле или откатить сборку;
инстансы с сервером при следующей выдаче получат `dns-mismatch` и поднимутся
заново.
