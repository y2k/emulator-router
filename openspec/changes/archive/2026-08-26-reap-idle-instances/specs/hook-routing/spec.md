## ADDED Requirements

### Requirement: Обработка события отмечает активность сессии и убирает простой

Обработка события хука SHALL начинаться с двух действий: отметки активности своей сессии в реестре и уборки записей, чьи сессии простаивают. Оба действия SHALL выполняться прежде разбора настроек проекта и прежде всех условий, при которых система в вызов не вмешивается, — и независимо от их исхода.

Отметка SHALL ставиться при любом обработанном событии, включая те, что заканчиваются пустым выводом: читающую проверку, нераспознанную команду, вызов из главного чекаута, вызов из проекта без файла настроек. Иначе сессия, работающая не с устройством, выглядела бы брошенной, и её инстанс отобрали бы у работающего.

Уборка по простою SHALL выполняться при обработке события независимо от того, обращается ли вызов за инстансом. Хук подключается общими настройками агента и приходит из любого проекта, поэтому любая живая сессия машины убирает за всеми — включая те случаи, до которых `SessionEnd` не доходит: аварийно завершённую сессию, спящую машину, сессию с неизвестным владельцем.

Ни отметка, ни уборка по простою не SHALL менять исход обработки вызова: в проекте без файла настроек вывод остаётся пустым, код возврата — нулевым, а вызов исполняется без вмешательства. Реестр один на машину, и ни для отметки, ни для уборки имя образа не требуется — как и для освобождения при завершении сессии.

#### Scenario: Событие в проекте без файла настроек

- **WHEN** приходит событие хука из проекта, для которого файл настроек не найден
- **THEN** активность сессии отмечается, простаивающие записи убираются, вывод пуст, код возврата равен 0

#### Scenario: Событие с негодными настройками

- **WHEN** приходит событие хука из проекта, чей файл настроек найден, но негоден
- **THEN** активность сессии отмечается, простаивающие записи убираются, а вызов блокируется, как того требует негодность настроек

#### Scenario: Читающая проверка

- **WHEN** приходит вызов, только опрашивающий состояние подсистемы отладки
- **THEN** активность сессии отмечается, инстанс не выдаётся

#### Scenario: Запрещённый вызов

- **WHEN** приходит вызов, который будет запрещён
- **THEN** активность сессии отмечается, простаивающие записи убираются, и решением остаётся запрет

#### Scenario: Завершение сессии

- **WHEN** приходит событие завершения сессии
- **THEN** инстанс этой сессии освобождается, а записи простаивающих сессий убираются
