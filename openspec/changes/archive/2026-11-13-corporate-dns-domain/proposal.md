## Why

Эмулятор на macOS берёт DNS-серверы из `/etc/resolv.conf`, а туда попадают
только основные резолверы машины. Резолверы split DNS, которые VPN заводит для
корпоративной зоны (`scutil --dns`, флаг `Supplemental`), эмулятор не видит.
Поэтому имена этой зоны в инстансе пула не резолвятся, и ошибок при этом нет:
загрузчик картинок молча отдаёт заглушку, а публичные имена работают. Проверено
на рабочем Android-проекте: хосты стенда `*.corp.example` резолвятся только
корпоративным DNS.

Спайк показал, что `-dns-server` снапшот загрузки не ломает. Он же показал, что
гость, восстановленный из снапшота, пользуется только первым сервером из списка,
так что запасного сервера нет. Значит, задавать адрес DNS-сервера в репозитории
нельзя: без VPN инстанс останется без DNS совсем. А выбрать «первый
supplemental-резолвер» — значит угадывать: на машине их бывает несколько
(VPN, Tailscale, Docker).

## What Changes

- Новое необязательное поле `dns` в `.claude/emulator-router.json`: домен,
  которому нужен корпоративный DNS, например `"dns": "corp.example"`. Если поля
  нет, пул ведёт себя как сейчас.
- Адрес сервера в настройках не задаётся. При выдаче инстанса роутер находит в
  конфигурации резолверов машины резолвер, который обслуживает этот домен, и
  запускает инстанс с `-dns-server <его первый сервер>`. Если такого резолвера
  нет (VPN выключен), инстанс запускается как сейчас.
- DNS-сервер становится частью идентичности инстанса наравне с образом. Если он
  разошёлся с текущим (VPN включили или выключили), инстанс освобождается, и
  сессия получает новый. Иначе инстанс с мёртвым или неполным DNS выдавался бы
  как исправный.
- Адрес вместо домена в поле `dns` делает файл настроек негодным (код 2): адрес
  в репозитории — это ровно та ошибка, которую изменение устраняет.
- `doctor` называет найденный для домена сервер либо предупреждает, что
  резолвера для домена на машине нет.
- Сначала рефакторинг без изменения поведения: форма запуска инстанса и
  сравнение его идентичности выносятся в одно место каждое, чтобы
  функциональность DNS легла отдельным файлом и подключалась одной строкой.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `pool-configuration`: в составе настроек появляется необязательный домен
  корпоративного DNS; адрес вместо домена делает файл негодным.
- `emulator-pool`: идентичность инстанса включает DNS-сервер; инстанс
  запускается с DNS-сервером домена проекта, если резолвер для домена на машине
  есть.
- `doctor`: проверка резолвера для домена корпоративного DNS.

## Impact

- `cmd/emulator-router/pool.go`: аргументы запуска и сравнение идентичности
  выносятся в отдельные функции; в записи реестра появляется поле `dns`.
- `cmd/emulator-router/dns.go` (новый): разбор `scutil --dns`, выбор сервера
  для домена, проверка для `doctor`.
- `cmd/emulator-router/main.go`: поле `dns` в `settings` и `config`, проверка
  значения.
- `cmd/emulator-router/doctor.go`: подключение проверки DNS.
- `cmd/emulator-router/router_test.go`, `doctor_test.go`: тесты.
- `README.md`: описание поля; `CLAUDE.md`: состав файлов и список настроек.
- Записи реестра прежних версий остаются совместимыми: без поля `dns` у них
  пустой сервер, и он совпадает с сервером проекта без настройки `dns`.
- Только macOS: на других системах `scutil` нет, резолвер не находится, и
  инстанс запускается как сейчас.
